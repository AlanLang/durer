01

代码不只是给人看的

把 React 组件写进页面，读者当场就能改、当场看到结果。

源码就写在 <script type="text/jsx"> 里，浏览器不会执行它，durer 会用 sucrase 在页面里即时编译、渲染。拖一下滑块，再去右边把 hsl 的亮度改成 40% 试试。

每个演示都关在自己的 Shadow DOM 里：演示里写的 label { … } 不会弄乱你的页面，页面的样式也漏不进演示。

动起来的也行

useEffect、requestAnimationFrame、指针事件都是真的。下面是一个弹簧跟随： 把鼠标移进框里，然后把 STIFFNESS 改大、DAMPING 改小，感受它变得多「弹」。

把代码改坏试试：删掉一个括号，下方会出现带行号的报错，而上面还留着上一版能跑的画面；改回来就恢复。 点标题栏的「重置」随时回到原始代码。

React 里也能画图

画图引擎 retikz 本身就是 React 组件，在演示里 import 进来， 图就成了状态的函数 —— 拖动滑块，环上的节点数跟着变。

长了就拆成多个文件

每个 <script> 写上 data-file，编辑器就变成标签页，文件之间用相对路径 import。样式也可以是一个文件：切到 style.css 把 .done 改个颜色， 列表里勾掉的事项不会丢 —— 改样式不重挂组件。

不懂的词，悬停就懂

解释不打断正文：想看的人停一下，不想看的人直接读下去。

TRY IT · 把鼠标停在带虚线的词上 浏览器渲染页面时，会先把 HTML 解析成 DOM， 再结合 CSS 算出每个元素的位置，这一步叫回流； 之后再把像素画到屏幕上。气泡挂在页面的顶层， 放在 overflow: hidden 的容器里也不会被裁掉。

05

一步一步来

过程类的知识，最好的讲法是把每一步摊开给读者看。

二分查找为什么快？因为每比较一次，候选区间就砍掉一半。下面这张图会自己播放；也可以点「下一步」、 点圆点，或者聚焦后按 ← → 翻页。整个过程只有一张图：它读当前的 step，决定哪些格子变暗、指针指向哪里。

每一步画的都是同一组节点，只改透明度、颜色和指针位置。节点不增不减，图的范围就不变，翻页时整张图稳稳地不跳。 <dr-step> 里也可以放每步各自的内容（代码、公式、任意 HTML），所有步骤叠在同一格，高度取最高的那一步。
06

公式也是一等公民

TeX 写进标签里，排版交给浏览器原生的 MathML。

还记得第一章的弹簧吗？那两行看起来随手写的代码，其实是 阻尼弹簧的离散形式。设目标位置是 x^{*}，每一帧：

v_{t+1} = d\,\bigl(v_t + k\,(x^{*} - x_t)\bigr), \qquad x_{t+1} = x_t + v_{t+1}

其中 k 就是代码里的 STIFFNESS，d 是 DAMPING。 d \lt 1 保证每帧都损失一点速度，所以球最终会停下来；d 越接近 1，晃得越久。

上一章的二分查找也一样能用一行说清：长度为 n 的数组，最多比较

\left\lceil \log_2 (n + 1) \right\rceil \ \text{次}, \qquad n = 9 \;\Rightarrow\; \lceil \log_2 10 \rceil = 4

刚才找 26 只用了 3 次，没有超过这个上限。
